# Pure Tree v1 永続形式

## 対象読者と使い方

探索木を保存・再読込するC++開発者向けの仕様です。ノードと辺を作り、ルートを設定してから `save_pure_tree` を呼びます。再利用時は `load_pure_tree` で読み込みます。読込時には形式・統計・木構造が検証され、不正なデータは例外になります。

## データモデル

Pure Tree は探索ノードと辺を保存するゲーム非依存の構造です。将棋局面の生成や識別子の作成方法は定めず、識別子は呼び出し側が指定します。

- ノードは一意な `id`、不透明な `position_identity` と `path_identity` を持ちます。
- 局面識別子と経路識別子の組は一意です。同じ局面でも異なる経路なら別ノードとして保持できます。
- 辺は一意な `id`、親・子ノードID、USI形式の着手を持ちます。
- 各ノードには訪問回数、勝数、敗数、引分数、平均評価値を保存します。
- 非ルートノードには親が1つ必要です。すべてのノードはルートから到達できなければなりません。循環、孤立ノード、複数の親を持つノードは拒否されます。
- 空木はルート・ノード・辺を持ちません。ノードがある木には既存ノードをルートとして設定します。

## 統計

勝数・敗数・引分数の合計は訪問回数以下でなければなりません。平均評価値は有限値かつ -1 以上 1 以下です。評価値の視点や計算方法は規定しないため、書き手と読み手で同じ規約を使ってください。

## ファイル形式

ファイルはUTF-8の行形式です。先頭行は `KADOKA_PURE_TREE<TAB>1`、次行は `ROOT` レコード、その後に `NODE` と `EDGE` レコードを置きます。各フィールドはタブで区切ります。辺の着手は通常形式（例: `7g7f`）、成り形式（例: `7g7f+`）、駒打ち形式（例: `P*5e`）を受け付け、それ以外は拒否します。

文字列フィールド内のバックスラッシュ、タブ、改行、復帰、および制御バイトは、それぞれ `\\\\`、`\\t`、`\\n`、`\\r`、`\\xHH` で表します。数値はロケールに依存しない形式で出力し、doubleは往復に十分な桁数を保持します。

未対応バージョン、不正なエスケープ、統計の矛盾、重複識別子、存在しない参照、不正な木構造は読み込み時に拒否されます。ファイル保存は既存ファイルを切り詰めて書き込み、flushとcloseの両方の結果を確認します。原子的な置換は保証しません。

## 範囲外

UCT/PUCT探索、Policy/Value補正、Auto Tuning、Model Hubはこの形式の対象外です。これらの機能は検証済みのノード・辺データを利用できます。
