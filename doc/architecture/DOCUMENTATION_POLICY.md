# 文書言語方針

## 目的と対象

Kadoka Shougi AIの利用者と主要な開発者が日本語話者であるため、設計・仕様・開発文書を日本語で一貫して読めるようにします。この方針はREADME、設計書、仕様書、開発ガイド、`AI_CONTEXT.md`などのAI向け入口文書、Issue、Pull Requestの設計説明に適用します。

## 正本の言語

- 新規文書と、この方針の導入後に改定する設計・仕様・開発内容は、日本語版を正本とします。
- 既存の英語文書を改定するときは、改定する内容に対応する日本語版を先に作成または更新し、相互リンクを設けます。
- 日本語正本に対応する英語版は補助翻訳として扱い、内容が異なるときは日本語版を正とします。
- 新しい文書は原則として日本語で作成します。外部との互換性などで英語が必要な場合は、その理由と日本語での説明を文書に記載します。

## 既存の英語文書の移行

[README](../../README.md)と[設計書](ARCHITECTURE.md)を含む既存の英語文書には、日本語版がまだない部分があります。その部分は移行が完了するまで英語原文を暫定正本として扱います。日本語版がないことを隠して、存在しない日本語正本を参照させません。

実装や仕様を変えるときは、変更対象の英語原文を読み、改定する節を節全体で日本語版へ移行してから改定します。部分移行先は同じディレクトリの`<stem>.ja.md`（例: `README.ja.md`、`ARCHITECTURE.ja.md`）とし、冒頭に対応する英語文書と移行済みの節を列挙します。日本語版がない節は英語原文が暫定正本です。移行済み節は日本語版を正本とし、英語側には日本語正本へのリンクと補助翻訳であることを示します。日本語版と英語原文を相互リンクし、READMEなどの索引から日本語版へ到達できるようにします。移行時は元文書の言語案内も更新します。

日本語版なしで既存英語文書へ追記できるのは、索引リンク、方針への参照、移行済み節の一覧だけです。仕様、設計判断、使い方の説明を変更するときはこの例外を使わず、対応する日本語版を追加します。全内容を一度に翻訳する必要はありませんが、英語だけの新しい仕様説明を増やしません。

## 用語と識別子

- class、function、API、schema、field、ファイル名、コマンド、規格名は、互換性と検索性を保つため必要に応じて英語表記を維持します。
- 英語の技術用語を使う場合も、文書全体の説明と判断理由は日本語で記載します。
- 外部標準名や既存の正式名称を独自に翻訳して意味を変えないようにします。

## 更新手順

1. 変更対象の日本語正本、または未移行部分の英語暫定正本と、参照するIssue・実装・テストを確認します。
2. 仕様や設計を変更するときは、先に日本語正本を更新します。
3. 英語の補助翻訳がある場合は、日本語正本の変更に合わせて更新します。
4. README、索引、相互リンクを更新し、読者が正本へ到達できることを確認します。
5. IssueとPull Requestでは、目的、変更範囲、判断理由、確認結果を日本語で説明します。

この手順は文章の言語を定めるものであり、実装や検証の完了を代わりに証明するものではありません。文書変更に伴うリンクやMarkdown構造の確認は、変更した範囲に合わせて行います。
