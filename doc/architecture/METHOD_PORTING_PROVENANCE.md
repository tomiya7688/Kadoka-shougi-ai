# 手法移植の出典・ライセンス記録

この文書は、Kadoka Shougi AIから兄弟プロジェクトへ、または兄弟プロジェクト・外部研究から手法を取り込むときに、出典、ライセンス、変更内容、判断理由を追跡できるようにする記録形式です。AI Model Metadataの `source` と `license` は配布モデルの要約情報に使い、この記録は個々の移植判断と根拠を保持します。

## 記録ルール

- 移植を検討した手法ごとに1件作成し、判断が「採用」「不採用」「保留」のいずれでも記録します。
- 出典には可能な限り不変のcommit、release、論文版、ファイルパスを記録します。変動するURLしかない場合は確認日と取得物のSHA-256を記録します。
- コード、モデル重み、データセット、画像・音声など、対象ごとにライセンスを確認します。リポジトリ全体のライセンスだけで第三者素材の利用可否を判断しません。
- ライセンスが不明、矛盾、または再配布条件を満たせない場合は、権利者への確認が済むまで採用・配布を保留します。
- 移植元の仕様をそのまま移すのではなく、ゲーム固有の規則、合法性の最終判断、依存方向、計算量、決定性を確認します。
- 「採用」は本記録だけで実装完了を意味しません。実装先、テスト、ベンチマークの証跡を別途リンクします。

## 記録テンプレート

この節を複製し、角括弧内を埋めて使用します。該当しない項目は「該当なし」とし、未確認項目を空欄のままにしません。

### [record_id] [手法名]

| 項目 | 記録 |
| --- | --- |
| 記録日・記録者 | [YYYY-MM-DD / 名前] |
| 判断状態 | [採用 / 不採用 / 保留] |
| 移植元プロジェクト | [repo URL] |
| 出典 | [issue / PR / 論文 / 書籍 / URL] |
| 不変の参照 | [commit SHA、release、論文版、ファイルパス] |
| 確認日・取得物hash | [日付 / SHA-256。不要なら理由] |
| 手法名・要約 | [正式名称 / 何をするか] |
| 対象プロジェクト・ゲーム | [移植先 / ゲーム] |
| 対象側追跡Issue | [Issue URL] |
| ライセンス対象 | [コード、重み、データ、その他を分けて記載] |
| ライセンス・根拠 | [ライセンス名 / 根拠文書・URL / 確認状態] |
| 必要な帰属・通知・再配布条件 | [条件と満たし方] |
| 適用可能性 | [移植先でも成立する条件、成立しない条件] |
| 期待する効果 | [測定対象と期待値。未測定なら未測定] |
| 計算・保守コスト | [計算量、依存、保守負担、測定値] |
| ゲーム固有の変更 | [ルール、状態、報酬、合法手、データ形式への変更] |
| 決定性・seed条件 | [seed、環境、再現条件] |
| 判断理由 | [採用・不採用・保留の理由] |
| 実装・検証証跡 | [PR、test、benchmark、artifact] |

### 判断の基準

- **採用**: 出典と利用条件を確認し、移植先の責務境界に適合し、期待効果と検証方法を説明できる。
- **不採用**: 利用条件を満たせない、前提が移植先に合わない、または効果に対してコストが大きいなど、採用しない根拠を記録できる。
- **保留**: 出典・ライセンス・適用条件・効果のいずれかが未確認で、採否を決める証拠が足りない。

## 関連する契約

配布モデルの共通metadataは[AI Model Metadata](../specifications/AI_MODEL_METADATA.md)を使います。ここには共有可能な`source`、`license`、`dataset_provenance`等の要約を記録し、詳細な移植判断は本記録から追跡します。
